[구조 최적화 / Structure]
  - Introduced Claude/skills/YYYY-MM-DD/skills/ date-indexed snapshots (matches the
    Claude/Changelogs <-> GPT/Changelogs and Claude/skills <-> GPT/skills convention).
  - Snapshot policy differs from GPT/skills intentionally: a new dated directory is written
    ONLY when the upstream version actually advances (checked via Claude/skills/.version),
    not unconditionally every day. GPT/skills/* currently writes a full dated snapshot daily
    regardless of change; Claude/skills avoids that to cut duplicate token/storage cost.
  - Canonical state stays a single file, SKILLS_CATALOG.yaml; dated folders hold a read-only
    copy of that file at sync time, not a re-expanded per-skill file set.

[토큰 절감 / Token savings]
  - Kept the single-YAML-catalog model instead of GPT's one-markdown-card-per-skill format:
    ~74 releases of changes were collapsed into 6 new/updated catalog entries instead of
    dozens of individual skill/hook cards.
  - Raw changelog excerpt in this report capped at ~3000 chars (see scripts/update_skills.py);
    full upstream text is never duplicated into the catalog itself.
  - Descriptions kept to one line; "note:"/"added:" fields only where they carry real signal
    (version provenance for audit), dropped otherwise.

[충돌 해결 / Conflict resolution]
  - CHANGELOGS_DIR moved from repo-root `changelogs/` (referenced by the old script but never
    actually created) to `Claude/Changelogs/`, mirroring `GPT/Changelogs/` and this routine's
    directory convention. No pre-existing files were at the old path, so no data was lost.
  - scripts/update_skills.py's version parser previously only captured the single newest
    "## x.y.z" section, silently dropping any intermediate releases when a sync was missed
    (as happened here: 73 releases were skipped between the last recorded 2.1.129 and today).
    Replaced with a range parser (parse_range) that walks every section back to the last
    recorded version, so future gaps are captured in full rather than losing history.
  - No naming collisions between new catalog keys and existing ones; all four new entries
    (code-review, deep-research, commit-push-pr, autofix-pr) were previously absent.
  - Fixed 3 pre-existing YAML syntax errors in SKILLS_CATALOG.yaml (unquoted colons inside
    parenthetical asides on the effort/tui/focus entries) that made the file fail
    yaml.safe_load; harmless in practice since the file was only ever regex-patched by
    scripts/update_skills.py, but corrected for hygiene since a routine that claims to
    "sync and validate" should leave the catalog machine-parseable.
